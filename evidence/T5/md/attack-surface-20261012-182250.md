## 5. 高价值入口 Top

### 1. `/forgot?username=<x>`（127.0.0.1:8095）

- 类型：Host 头注入 / 弱口令重置 token
- 证据：实测 X-Forwarded-Host: evil.example → <pre>http://evil.example/reset?user=demo&token=fe01ce2a7fbac8fafaed7c982a04e229</pre>
- 价值：token=md5(username) 完全可预测；若存在 /reset 消费端即可任意用户改密（当前该路由不存在，需确认消费面）
- 状态：已实测（回显层面）

### 2. `/debug`（127.0.0.1:8095）

- 类型：敏感信息泄露（SECRET_KEY）
- 证据：debug_page() 输出 DEBUG/SECRET_KEY/DB_PATH/BASE_DIR/UPLOAD_DIR/cwd；KEY 常量 lab-secret-key-PLEASE-CHANGE-001（app.py:42）
- 价值：拿到 SECRET_KEY = 可离线伪造任意会话的 CSRF token（HMAC(SECRET_KEY, token)），配合 GET 写入口放大
- 状态：代码级证据 + 未登录 302/非 admin 403 实测；admin 成功响应未复现（阶段2不登录 admin）

### 3. `GET /wallet/withdraw?amount=N（及 /order/create、/order/status、/coupon/claim）`（127.0.0.1:8095）

- 类型：无方法限制的状态变更 + 无 CSRF（GET 即可触发）
- 证据：route() 后各 handler 只判断 self.command=='POST' 决定分支；withdraw 无 CSRF 校验；实测 GET 进入 400 校验分支
- 价值：诱使已登录用户访问一个 GET 链接即可扣余额/领券/改单状态（CSRF），且 money 类接口
- 状态：代码级证据已确认；扣款成功路径未实测（只读约束）

### 4. `POST /board（匿名）+ GET /board 输出`（127.0.0.1:8095）

- 类型：匿名内容写入 / 存储型注入候选
- 证据：board() POST 无需登录，author=anonymous；输出 html.escape（当前无 XSS）
- 价值：任何匿名者都能污染留言板；后续若与 admin 浏览面联动即是存储型 XSS 入口
- 状态：代码级证据；未写帖

### 5. `GET /fetch?url=`（127.0.0.1:8095）

- 类型：内网回环探测（受限 SSRF）
- 证据：实测 /fetch?url=http://127.0.0.1:8095/ → 200 原样回显；非 127.0.0.1 → 403；端口白名单 {80,443,8080,8081,8082,8090,8091,8092,...}
- 价值：可探测本机白名单端口存活/内容（8091 已在白名单内），是横向侦察跳板
- 状态：已实测

### 6. `GET /（已登录会话）`（127.0.0.1:8095）

- 类型：功能性缺陷（认证态首页 500）
- 证据：lab_errors.log 多次记录 app.py:513 AttributeError: 'sqlite3.Row' object has no attribute 'get'；实测带 token cookie 的 GET / → 500
- 价值：登录后首页必崩，影响可用性；同时暴露未处理异常路径
- 状态：已实测（复现条件：带有效会话 cookie）

### 7. `/api/profile?id=、/api/orders?id=`（127.0.0.1:8091）

- 类型：越权/枚举面（当前已封堵）
- 证据：demo 会话查 id=3 → 404 且审计 api_forbidden；未登录 → 401
- 价值：历史漏洞面，需挖掘阶段用新会话/边界值复测（例如 id=0、超大 id、数组参数）
- 状态：已实测为封堵

### 8. `/register`（127.0.0.1:8091）

- 类型：用户枚举（差异化 msg）
- 证据：重名 → ?m=exists；其他非法 → ?m=invalid（303 Location 差异）
- 价值：可枚举已存在用户名（demo/alice 已知，价值有限）
- 状态：已实测
