# 7 问验证门与永不提交黑名单

> 来源：Agentic-Bug-Hunter triage-validation 方法论，结合本项目实战经验整理。
> 用途：任何漏洞在写报告之前，必须通过这 7 个问题。一个答错 = 杀掉，不写报告。

---

## 一、7 问验证门（按顺序问，一个答错立即停止）

### Q1：能写出完整可复现的 HTTP 请求吗？

必须能填完这个模板：

```
1. 前置条件：我需要 [自己的账号 / 另一个用户的 ID / 无需账号]
2. 请求：[精确的 HTTP 方法、URL、Header、Body — 可直接复制粘贴复现]
3. 结果：我能 [读取 / 修改 / 删除] [响应中显示的精确数据]
4. 影响：真实后果是 [账号接管 / PII 泄露 / 资金损失]
5. 成本：时间 [X 分钟]，资金 [$0 / 需要 $X 订阅]
```

**如果第 2 步写不出真实 HTTP 请求 → 杀掉。**

### Q2：影响在项目接受范围内吗？

去项目页面查"漏洞类型"或"超出范围"。常见分级：

| 等级 | 典型漏洞 |
|---|---|
| 严重 | 任意用户无交互 ATO、RCE、SQLi 拖库、管理员认证绕过 |
| 高危 | 大规模 PII 泄露、权限提升、带回显的内网 SSRF、影响所有用户的存储 XSS |
| 中危 | 特定用户非关键数据 IDOR、需点击的敏感页面 XSS |
| 低危 | 非敏感信息泄露、有 PoC 的点击劫持 |

**如果你的洞在排除列表里 → 杀掉。**

### Q3：根因在授权范围内的资产上吗？

确认：
- 漏洞域名在范围内（不是 `*.internal.target.com`）
- 是生产资产（除非 staging/dev 明确在范围内）
- 不是公司只是用了的第三方服务（不是 Stripe、Salesforce、Google Auth）

**如果超出范围 → 杀掉。**

### Q4：需要攻击者无法现实获得的权限吗？

- "管理员能做 X" = 集中化风险 = **杀掉**（99% 的项目）
- "非管理员能做只有管理员该做的事" = 有效
- "需要物理访问 / MFA 设备" = 通常无效
- "需要先攻陷受害者账号" = 存疑，最多低危

### Q5：是已知或被接受的行为吗？

搜索：
1. 项目的 HackerOne/Bugcrowd 已公开报告：Ctrl+F 端点名 + 漏洞类型
2. 目标仓库的 GitHub Issues：`is:issue label:security 端点名`
3. CHANGELOG — 有没有提到这个行为
4. API 文档 / 设计文档 — 有没有写这是预期行为

**如果是已确认的 / 设计决策 → 杀掉。**

### Q6：能证明超越"理论可行"的影响吗？

| 漏洞类型 | 必须证明的（不是这个就降级） |
|---|---|
| XSS | 实际 Cookie 窃取或会话劫持，不是 `alert(1)` |
| SSRF | 打到返回数据的内部端点，不是只有 DNS ping |
| SQLi | 从真实表拖出实际数据，不是只有错误信息 |
| IDOR | 响应中实际显示其他用户数据，不是只有 200 状态码 |

**如果只能证明"理论可行" → 降级严重程度，不杀掉。**

### Q7：在"永不提交"黑名单上吗？

见下方黑名单。如果在上面且没有链化利用 → **杀掉。**

### Q8（补充）：身份检查 — 哪个会话发现的，能跨身份复现吗？

对于任何认证态下发现的漏洞，记录：

```
1. 会话 ID：[12 字符哈希]
2. 身份：[低权限用户 A / 高权限用户 B / API Key]
3. 匿名复现：不带 auth header 的同样请求还能工作吗？
4. 跨身份：用会话 B 同样的数据范围还能工作吗？
5. 过期凭证复现：登出 / 过期会话还能拿到数据吗？
```

为什么重要：
- **IDOR / BOLA**：必须是会话 A 读会话 B 的数据 — 如果只在无认证时工作，那是"缺少认证"不是 IDOR
- **权限提升**：必须是低权限会话读高权限数据 — 如果两个会话都能看到，没有洞
- **认证绕过**：必须在*没有*有效会话时工作 — 如果登出后就不工作了，你发现的是权限问题不是绕过

**如果答不出身份问题，当作未证明。认证相关漏洞空白答案自动失败。**

## 二、4 道提交前关卡（全部通过才能提交）

### 关卡 0：现实检查（30 秒）

```
[ ] 漏洞是真的 — 用实际 HTTP 请求确认，不是只读代码
[ ] 漏洞在范围内 — 明确查过项目范围页面
[ ] 可从零复现 — 从新会话开始能复现
[ ] 证据就绪 — 截图、响应体或视频
```

### 关卡 1：影响验证（2 分钟）

```
[ ] 能回答："攻击者能做什么他们之前不能做的事？"
[ ] 答案超越"看到非敏感数据"（除非项目为信息泄露付费）
[ ] 真实受害者：其他用户数据、公司数据、资金损失
[ ] 不依赖受害者做不太可能的事
```

### 关卡 2：去重检查（5 分钟）

```
[ ] 搜过 HackerOne Hacktivity 这个项目 + 类似漏洞标题/端点
[ ] 搜过目标仓库的 GitHub Issues
[ ] 读过这个项目最近 5 份公开报告
[ ] 不是他们 changelog 或公开文档里的"已知问题"
[ ] Google 搜过："项目名 端点名 bug bounty"
```

### 关卡 3：报告质量（10 分钟）

```
[ ] 标题：[漏洞类型] in [端点] allows [角色] to [影响]
[ ] 复现步骤：可复制粘贴的 HTTP 请求
[ ] 证据：实际影响的截图/视频（不是只有 200 状态）
[ ] 严重程度：匹配 CVSS 3.1 分数 AND 项目的严重程度定义
[ ] 修复建议：1-2 句具体修复
[ ] 从未使用"可能"、"也许"、"理论上可以"
```

## 三、永不提交黑名单

提交这些会毁掉你的有效率：

```
缺少 CSP / HSTS / 安全响应头
缺少 SPF / DKIM / DMARC
只有 GraphQL introspection（无后续认证绕过或 IDOR）
只有 Banner / 版本泄露（无可用 CVE 利用）
非敏感页面的点击劫持（无敏感操作 PoC）
Tabnabbing
CSV 注入（无实际代码执行证明）
CORS 通配符 * 但无凭证窃取 PoC
登出 CSRF
Self-XSS（只攻击自己账号）
单独的开放重定向（无 ATO 或 OAuth 窃取链）
移动 App 里的 OAuth client_secret（已知、预期）
SSRF 只有 DNS 回调（无内部服务访问或数据）
单独的 Host 头注入（无密码重置投毒 PoC）
非关键表单的速率限制缺失（搜索、联系、有 Cloudflare 的登录）
登出不销毁会话
并发会话
错误信息中的内部 IP
混合内容
SSL 弱密码
单独缺少 HttpOnly / Secure cookie 标志
损坏的外部链接
密码字段的 autocomplete
预账号接管（通常 — 需要非常特定的条件）
```

## 四、常见 N/A 类型 — 杀掉信号

这些能通过基本的直觉检查，但最后**稳定判为 N/A**。每行都给了一个**特定信号**，告诉你在写报告之前就该把它杀掉：

| 发现 | 为什么 N/A | 杀掉信号 — 看到就停 |
|---|---|---|
| 反射型 XSS | CSP 阻止执行；沙箱上下文；无会话访问 | Dalfox 找到 `alert(1)` 但响应中无 cookie；有 `Content-Security-Policy` 头 |
| SSRF — 只有 DNS 回调 | 没到达内部数据；项目要求带数据的 HTTP 响应 | Interactsh/Collaborator 收到 DNS ping 但无带内部内容的 HTTP 回复 |
| IDOR — 只有自己数据 | 攻击者 == 受害者；未证明跨账号访问 | 响应中的用户 ID 匹配你自己的测试账号 |
| SQLi — 只有错误信息 | WAF 过滤或错误是装饰性的；无数据拖出 | 得到 DB 错误字符串但无实际表行返回 |
| CORS 通配符 `*` | `*` 阻止 `withCredentials`；无 PII 实际泄露 | 缺少 `Access-Control-Allow-Credentials: true`；带凭证请求返回 403 |
| 非敏感端点缺速率限制 | 项目只为认证/支付/OTP 表面的速率限制付费 | 端点处理搜索、联系表单，或在 Cloudflare 后面 |
| Nuclei `info` 模板匹配 | 版本检测，不是利用 | 模板严重程度是 `info`；无 CVE PoC 对实时服务执行 |
| MFA 速率限制（无锁定） | 影响取决于 OTP 暴力成功 — 通常不会 | 15 个请求返回 200 但没有 OTP 码被接受 |
| 单独开放重定向 | 重定向是信息性的，无令牌窃取链 | 无 OAuth `redirect_uri` 参数；重定向 URL 中无认证码或令牌 |
| 认证绕过 — 管理员前置条件 | 需要先攻陷管理员才能触发；攻击者到不了那里 | "管理员可以代表用户做 X" — 攻击者必须已经是管理员 |
| 通过 `alert(document.domain)` 的 XSS | 不是会话窃取的证明 | PoC 只显示域名弹窗；无 `document.cookie` 泄露，无事件监听器 |
| SAML 元数据暴露 | 只是泄露 — 有助于攻击但不是独立影响 | 未提取私钥或签名证书；元数据是 IdP 公开记录的 |

**决策规则：如果你的发现匹配杀掉信号 → 分类为 `[信息性]`，不要跑验证，继续前进。**

## 五、有条件有效 — 需要链化

先建好链，证明端到端工作，**然后**再报告：

| 单独发现 | 需要的链 | 有效结果 |
|---|---|---|
| 开放重定向 | + OAuth redirect_uri → 认证码窃取 | ATO（严重） |
| 点击劫持 | + 敏感操作 + 可用 PoC | 中危 |
| CORS 通配符 | + 带凭证请求泄露用户 PII | 高危 |
| CSRF | + 敏感操作（转账、改邮箱、删账号） | 高危 |
| 速率限制绕过 | + OTP/重置令牌暴力成功 | 中危/高危 |
| SSRF 只有 DNS | + 内部服务访问 + 返回数据 | 中危 |
| Host 头注入 | + 密码重置邮件使用注入的 host | 高危 |
| 提示注入 | + 读取其他用户数据（IDOR） | 高危 |
| S3 桶可列 | + JS bundle 包含 API Key 或 OAuth 密钥 | 中危/高危 |
| Self-XSS | + CSRF 在受害者不知情时触发 | 中危 |
| 子域名接管 | + 在该子域名注册 OAuth redirect_uri | 严重 |
| GraphQL introspection | + 认证绕过 mutation 或 node() 上的 IDOR | 高危 |

## 六、快速杀掉规则

目标是**快速淘汰坏线索**以便挖真洞：

1. **5 分钟规则**：如果 5 分钟内填不完 Q1 模板 → 换目标
2. **前置条件计数**：同时需要超过 2 个前置条件 → 杀掉
3. **影响测试**："攻击者能带走什么？" — 如果没有实质东西 → 杀掉
4. **管理员绕过**："管理员能做 X" 永远不是洞 → 立即杀掉
5. **设计文档测试**：如果是文档记录的行为 → 立即杀掉
6. **兔子洞信号**：在 Q6 上花 30+ 分钟无可复现 PoC → 杀掉

## 七、亏钱的反模式

```
在确认漏洞存在之前就写报告（最常见）
提交没有证明的理论影响
"API 返回的字段比必要的多"（敏感性才重要 — 真的敏感吗？）
把 A+B 链写成一份报告，而它们是独立的洞（应该是两笔独立赏金）
报告 B 时说"类似于我另一份报告里的 A" — 每个洞都要重新过关卡 0
过度声称严重程度 — 分类员下次就不信任你了
描述影响不足 — 分类员不明白为什么重要
```
