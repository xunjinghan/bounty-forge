# 漏洞链方法论：A → B → C 集群狩猎

> 来源：Agentic-Bug-Hunter bug-bounty 方法论，结合本项目实战经验整理。
> 核心原则：单漏洞给钱少，漏洞链给 3-10 倍。发现漏洞 A 后，系统地在附近找 B 和 C。

---

## 一、为什么漏洞链更值钱

| 维度 | 单漏洞 | 漏洞链 |
|---|---|---|
| 典型赏金 | $50 – $500 | $500 – $10,000+ |
| 严重程度 | 低-中 | 高-严重 |
| 竞争 | 高（大家都找单洞） | 低（需要组合思维） |
| 报告说服力 | "这里有个洞" | "这个洞能导致账号接管" |
| 修复优先级 | 低 | 高（业务影响明确） |

**一句话：发现 A 只是开始，链化 A→B→C 才是赏金。**

## 三、6 步集群狩猎协议

```
1. 确认 A      用真实 HTTP 请求验证漏洞 A 是真的
2. 映射兄弟端点  找到同一控制器/模块/API 组下的所有端点
3. 测试兄弟端点  对每个兄弟端点应用相同的漏洞模式
4. 链化         如果兄弟有不同漏洞类型，尝试组合 A + B
5. 量化影响     "影响 N 个用户" / "暴露 $X 价值" / "N 条记录"
6. 报告         一条链一份报告（不是一个洞一份）。链给更多钱。
```

### 第 1 步：确认 A

- 必须有真实 HTTP 请求和响应
- 必须有可复现的 PoC
- 记录受影响的端点、参数、方法

### 第 2 步：映射兄弟端点

从以下来源找兄弟：
- 同一控制器下的其他路由（读源码或路由表）
- 同一 API 版本下的其他端点（`/api/v1/users/` → `/api/v1/orders/`）
- 同一功能模块的其他操作（读 → 写 → 删 → 导出）
- JS bundle 中发现的 API 调用
- 目录爆破发现的相邻路径

### 第 3 步：测试兄弟端点

对每个兄弟端点：
- 应用相同的漏洞模式（如果 A 是 IDOR，兄弟也试 IDOR）
- 测试不同的 HTTP 方法（GET 有洞 → 试 PUT/POST/DELETE）
- 测试不同的参数位置（URL 参数 → Body 参数 → Header）
- 测试不同的 API 版本（v2 有洞 → 试 v1）

### 第 4 步：链化

如果兄弟端点有不同的漏洞类型：
- 尝试组合：A 的输出作为 B 的输入
- 示例：调试端点泄露 SECRET_KEY（A）→ 用密钥伪造 CSRF 令牌（B）→ 执行转账（C）
- 示例：开放重定向（A）→ OAuth 认证码窃取（B）→ 账号接管（C）

### 第 5 步：量化影响

- 影响多少用户？（"所有注册用户" vs "特定条件用户"）
- 暴露什么数据？（PII / 支付信息 / 内部文档）
- 资金影响？（"可无限积分" vs "单次最多 $X"）
- 攻击成本？（"只需免费账号" vs "需要 $X 订阅"）

### 第 6 步：报告

- **一条链一份报告**，不是一个洞一份
- 报告标题要体现链的最终影响，不是第一个洞
- 坏标题：`IDOR in /api/users/{id}`
- 好标题：`IDOR in /api/users/{id} allows full account takeover via password reset chain`
- 复现步骤要展示完整链，不是只展示 A

## 四、真实案例

### 案例 1：Coinbase S3 → Bundle → Secret → OAuth 链

```
A: S3 桶公开可列（单独只有低危）
B: JS bundle 包含 OAuth client credentials
C: OAuth 流程缺少 PKCE 强制
结果：完整认证码拦截链
```

### 案例 2：本项目 VULN-03 链（loop3 实战）

```
A: /debug 端点泄露 SECRET_KEY（中高）
B: CSRF 令牌 = HMAC-SHA256(SECRET_KEY, session_token) → 可离线伪造
C: POST /wallet/transfer 转账 5000 分 → admin 100000→95000
结果：从信息泄露到资金损失的完整链（高危）
```

### 案例 3：Vienna Chatbot 链

```
A: 生产环境调试参数激活（单独只有信息性）
B: Chatbot 在响应中渲染 HTML（dangerouslySetInnerHTML）
C: 通过 bot 响应的存储 XSS 对其他用户可见
结果：有真实影响的 P2 发现
```

## 五、链化思维训练

### 问自己这些问题

发现任何漏洞后，立即问：

1. **这个洞的输出能作为另一个洞的输入吗？**
   - 泄露的密钥 → 能伪造什么？
   - 泄露的路径 → 能穿越到哪里？
   - 泄露的凭证 → 能登录哪里？

2. **这个洞在哪些兄弟端点上也存在？**
   - 同控制器的其他路由
   - 同功能的其他操作
   - 同 API 的其他版本

3. **这个洞能和什么常见漏洞组合？**
   - 信息泄露 + 认证绕过 = ?
   - XSS + CSRF = ?
   - SSRF + 云元数据 = ?

4. **这个洞的最终业务影响是什么？**
   - 不只是"有个洞"，而是"攻击者能做什么"
   - 账号接管？资金损失？数据泄露？服务中断？

### 链化检查清单

```
[ ] 已确认 A 是真洞（有 PoC）
[ ] 已映射同控制器/同模块/同 API 版本的所有兄弟端点
[ ] 已对每个兄弟端点测试相同漏洞模式
[ ] 已测试不同 HTTP 方法（GET/POST/PUT/DELETE）
[ ] 已测试不同参数位置（URL/Body/Header）
[ ] 已寻找 A 的输出可作为 B 的输入的组合
[ ] 已量化最终业务影响（用户数/数据类型/资金量）
[ ] 报告标题体现最终影响，不是第一个洞
[ ] 复现步骤展示完整链
```
