# 提交前自查清单（107 项 · 每项含「怎么验证」）

> 配套：`漏洞盒子报告模板-提交版.md` v2（2026-10-13，loop4 t5）。
> 用法：写完报告后**逐项勾选**。每项格式：**一句话判据 —— 验证：具体怎么查**。
> 验证方法全部可执行（搜什么、看哪一条、跑什么），不是"认真检查一下"。
> 标「loop3」的项来自 loop3 C1/C2 实战 —— 这些是真实踩过的坑，不是假想。

> ⚠️ **本清单不承诺「通过审核」。** 审核标准由平台掌握，本清单只能保证
> 「该有的证据都在、路线没标错、量化判据过了」，**不能**保证结果。
> 模板 v2 严格对照 rubric，**未达 3 级不得标 3**。

- [ ] **I01** 漏洞标题格式为 `[类型] 位置 参数 存在 问题`，一句话含位置+类型+危害 —— 验证：看标题是否符合这个格式。
- [ ] **I02** 漏洞简述是 1–2 段讲发现过程+成因，**没有**长篇原理解释 —— 验证：看简述段长度，应简短。
- [ ] **I03** 复现过程按**人实际操作流程**写（账号准备→抓包→改参→重放→看结果）—— 验证：看流程顺序，是否是操作流水。
- [ ] **I04** 漏洞验证段落写明截图附件**包含哪些内容**、标注了哪个敏感字段 —— 验证：看验证段，有附件说明和字段标注。
- [ ] **I05** 实际影响分**直接危害**与**延伸影响**两层，延伸不推演到沦陷 —— 验证：看影响段，是否分两层且延伸不过度。｜模板
- [ ] **I06** 修复建议 3 条左右，每条**可落地**（接口/校验/日志/限流）—— 验证：看修复条数与具体性。
- [ ] **I07** 结尾有**测试声明**（固定短句：仅做验证、无破坏、符合协议）—— 验证：看结尾，应有这句。
- [ ] **I08** 归档版七节（原理/影响面/复现步骤/危害证明/修复/参考/关联发现）**齐全** —— 验证：数七个二级标题是否都在。｜模板
- [ ] **I09** 反序列化类归档版有「判据校准记录」节（假 oracle 证伪）—— 验证：找该节，应有判据对照表。｜模板 §2.1
- [ ] **I10** 归档版有「阴性清单」节，每条说明不通过的原因类型 —— 验证：找阴性清单，逐条看原因。｜模板 §2.1
- [ ] **I11** 归档版有「隔离与安全声明」表，含物理网卡可达性 —— 验证：找该表，确认含 H03 那行。｜模板 §2.1
- [ ] **I12** 归档版有「引用存在性自检」节，命令可复跑 —— 验证：找那段命令，复制能跑出 missing=0。｜模板 §2.1

## J 组 · 人工复核（强制，AI 不能替代）

- [ ] **J01** 本人按报告步骤在目标上**重新走一遍**，确认可复现 —— 验证：亲手执行复现步骤，记录结果。
- [ ] **J02** 确认目标在**授权范围**，测试时间符合项目规则 —— 验证：核对授权书与时间戳。
- [ ] **J03** 确认没把**其他测试者/自己其他会话的脏数据**当成漏洞 —— 验证：查数据来源，确认是本会话产物。｜loop3 C2
- [ ] **J04** 确认报告里的每个 sha256 都**实读文件重算**过，不是转录的 —— 验证：`Get-FileHash` 抽查比对。｜loop3 C1/C2

- [ ] **J07** 确认这份报告是**自己写的**（或逐句人工复核），不是直接把 AI 输出投出去 —— 验证：能逐句解释每处措辞为什么这么写。｜loop3
