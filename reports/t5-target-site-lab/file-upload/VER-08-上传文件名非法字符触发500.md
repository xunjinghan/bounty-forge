# 漏洞笔记：上传文件名未做字符集/保留名校验（Windows 非法字符与 NUL 触发未处理异常 500）

- **编号**：VER-08（来源 HUNT-08，t5 判定 confirmed）
- **靶场**：target-site-lab `http://127.0.0.1:8095`（本机授权练习环境，Windows 主机）
- **危害等级**：低危（Low，可用性/异常面，无文件落地）
- **CWE/OWASP**：CWE-475（Undeclared Behavior / 未定义行为类的非法输入处理）＋ CWE-248（Uncaught Exception）；OWASP Top 10 2021 **A04:2021 Insecure Design（输入校验不全）**
- **CVSS-like**：3.7（AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:L）
- **复现率**：3/3 触发（`296×'a'.txt` → 500 `OSError [Errno 22]`；`<b>tag</b>.txt` → 500 `OSError`；`nul\x00name.txt` → 500 `ValueError: embedded null character`）
- **代码位置**：`target-site-lab/app.py:813-868`（`upload`，关键行 841-854）

---

## 1. 漏洞概述

上传处理只做了两件事：`os.path.basename()` 清洗路径 + 后缀白名单/MIME 魔数校验（`app.py:841-850`）。**文件名本身没有字符集校验、没有长度限制、没有 Windows 保留名/非法字符过滤**，并且 `open()` 未做异常兜底。于是含 Windows 非法字符（`<`、`>`）或 NUL 字节、或超长（296 字符）的文件名会让 `open(dest, "wb")` 抛异常 → 500。

**边界（比只写"500"更重要）**：这三个载荷**都没有文件落盘**（`uploads/` 保持为空），所以不属于"任意写/DOS 磁盘满"；它暴露的是**错误处理缺失**与**平台相关输入处理不当**。同时因为公开可达（无认证），任何人可反复触发 500 并往 `lab_errors.log` 写堆栈。

补充实测（与 VER-16 同源）：匿名可上传**合法**文件（`verifier_ok.txt`、`semi;name.txt`、`shell.txt` 均落盘成功），说明该端点连认证都没有。

> 本笔记包含**两条**判定，隶属同一入口 `POST /upload`：主体为 **VER-08**（文件名非法字符/超长/NUL → 500），文末附 **VER-16**（匿名可用，可无限写入 `uploads/`）。合并归档理由见 `progress.md §3 归档说明`（captain 于 2026-10-12 批准维持合并、不拆分）。

## 2. 原理（代码层根因）

```python
# target-site-lab/app.py:841-854（节选）
safe_name = os.path.basename(filename)          # L841 只防路径穿越
ext = os.path.splitext(safe_name)[1].lower()
if ext not in UPLOAD_ALLOWED_EXT:               # L844 后缀白名单
    rejected.append((filename, "后缀不在白名单"))
    continue
if not self._check_mime(ext, content):           # L848 MIME 魔数
    rejected.append((filename, "文件内容与扩展名不匹配"))
    continue
dest = os.path.join(UPLOAD_DIR, safe_name)      # L851
with open(dest, "wb") as fh:                    # L852 ← 无 try/except
    fh.write(content)
```

三个缺口：

1. **字符集**：`basename` 不会剔除 `<`、`>`、`:`、`|`、`"` 等在 Windows/NTFS 上非法或语义特殊的字符；`\x00` 直接让 Python 的 `open()` 抛 `ValueError: embedded null character`。
2. **长度**：未限制文件名长度。Windows 组件（含扩展名）超过约 255 字符即触发 `OSError [Errno 22]`；296 字符的 `a...a.txt` 正好命中。
3. **异常处理**：`open()` 没有 `try/except OSError`，异常冒泡→500，并把完整绝对路径堆栈写进 `lab_errors.log`（堆栈含盘符路径，属信息外泄的次生问题）。

顺带注意：**清洗后用于落盘的名字（`safe_name`）与回显给用户的名字（`filename` 原值，`app.py:863`）不是同一个**，评测时就容易误判"到底落盘成什么名"。本笔记统一以 `safe_name` 为落盘名的判定依据。

## 5. 修复方案

### 代码级（P1，落到 `app.py:841-854`）

```python
IMPORT_FORBIDDEN = set('<>:"/\\|?*') | {chr(c) for c in range(32)}   # 含 NUL 与控制字符
WIN_RESERVED = {"CON", "PRN", "AUX", "NUL", "COM1", "LPT1"}          # 按需补全

safe_name = os.path.basename(filename or "")
# ① 长度限制（含扩展名）
if len(safe_name) > 128:
    rejected.append((filename, "文件名过长"))
    continue
# ② 字符集与保留名校验
stem = os.path.splitext(safe_name)[0].upper()
if any(ch in IMPORT_FORBIDDEN for ch in safe_name) or stem in WIN_RESERVED:
    rejected.append((filename, "文件名含非法字符"))
    continue
# ③ 落盘异常兜底
dest = os.path.join(UPLOAD_DIR, safe_name)
try:
    with open(dest, "wb") as fh:
        fh.write(content)
except OSError:
    rejected.append((filename, "写入失败"))
    continue
```

更稳的做法：**不采用用户提供的文件名**——用服务端生成的随机名（`uuid.uuid4().hex + ext`）落盘，原始文件名只存元数据表，下载时再按元数据设置 `Content-Disposition`。这样从根上消除"文件名即路径片段"的所有变体问题（保留名、非法字符、长度、大小写冲突、覆盖已有文件）。

### 纵深防御

- **上传面认证**：`/upload` 当前匿名可用（VER-16）——加登录要求或一次性令牌，至少做 IP 级频控与总量配额。
- **落盘目录隔离**：`uploads/` 与代码目录分离，且永远以 `application/octet-stream` + `attachment` 返回（本项目已做，`app.py:905-916`，保持）。
- **错误处理规范**：文件系统操作全部包 `try/except OSError`，把"输入导致的失败"返回 4xx，不让其变成 500；日志里的堆栈不要包含对外可见路径（写相对路径）。
- **回归用例**：文件名集合 `{超长、含 <>、含 NUL、保留名 CON.txt、仅扩展名 .txt、双扩展 .txt.php}` 全部要求 4xx 且不产生 500、不落盘。

## 7. 学习要点

- **考什么思路**：上传点的输入面有**三个维度**——①内容（MIME 魔数）②后缀（白名单）③**文件名**（字符集/长度/保留名）。本靶场把①②做得很好（假 `.jpg` 会被 400 拒绝），漏的恰恰是③。
- **平台差异是坑**：同一文件名在 Linux 落盘成功、在 Windows 直接 `OSError`。测试时要以**目标运行平台**为准，别用自己机器的行为推断。
- **"异常"与"利用"要分开定级**：本项只产生 500、不落盘、不覆盖文件，所以定 Low；如果同一条路径能做到**覆盖已有文件**（如 `exploit.txt` 覆盖配置）或**写进不可预期目录**，等级立刻上升。
- **同类变体**：
  - 文件名覆盖（上传同名文件覆盖他人成果/系统文件）。
  - 双扩展名与后缀大小写（`.PHP`、`.php.`、`.php%00.jpg`）。
  - Unicode 归一化与大小写折叠导致的同名冲突（`ﬁle.txt` vs `file.txt`）。
  - 落盘名与展示名不一致，导致"下载他人文件"或"路径穿越在展示层被隐藏"。

## 附：VER-16 匿名上传

> 与 VER-08 同属入口 `POST /upload`、同属 `app.py:813-868` 代码路径；本节独立成节以便检索（captain 2026-10-12 裁决：维持与 VER-08 合并归档，不拆分）。

- **编号**：VER-16（t5 本轮新增发现，非 hunter 原始 15 条之一；判定 confirmed）
- **危害等级**：低危（Low，匿名存储占用面）
- **CWE/OWASP**：CWE-306（Missing Authentication for Critical Function，匿名可写）＋ CWE-770（Allocation of Resources Without Limits or Throttling，单文件 5MB 上限、无总量与频控）；OWASP Top 10 2021 **A01:2021 Broken Access Control / A04:2021 Insecure Design**
- **CVSS-like**：3.1（AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:L/A:N）
- **复现率**：2/2（`verifier_ok.txt`、`semi;name.txt` 均匿名落盘）
- **代码位置**：`target-site-lab/app.py:813-854`（`upload()` **不调用 `require_user`**；上限检查在 `:831-833`）

### 概述

无 Cookie 的 multipart `POST /upload` 直接落盘并返回 200——该端点**没有认证**。单文件上限 5MB（`MAX_UPLOAD_BYTES`，`app.py:831-833`），但**无总量配额、无频控**，可逐个文件把磁盘写满，也可作为匿名文件托管（存放/分发任意文本内容）。

### 原理（代码层根因）

```python

def upload(self):
    if self.command != "POST":                 # L814 只判方法，不判身份
        ...（渲染上传页）

    ...
```

对照同文件其它需登录的入口（如 `order_create` 在 `:925`、`board` 的写分支在 `:747`），`upload()` 全程没有 `self.require_user(conn)`，也没有任何令牌/验证码校验——匿名即写入。

### 修复方案

**代码级（P0，落到 `app.py:813-822`）**

```python
def upload(self):
    conn = get_db()
    try:                                    # 新增：上传必须登录
        user = self.require_user(conn)
        if not user:
            return
        if not rate_limit_ok(self.client_address[0]):        # 新增：IP 级频控（复用 VER-07 的写法）

        if used >= MAX_TOTAL_UPLOAD_BYTES:
            self.html(507, page("507", "<h1>存储空间已满</h1>"))
            return
    finally:
        conn.close()
    ...（其余逻辑不变）
```

**纵深防御**

- **落盘名随机化**：用服务端生成的 `uuid4().hex + ext` 替代用户文件名（同时消除 VER-08 的一整族问题）。
- **配额与清理**：按用户/时间窗限制文件数与字节数，定期清理匿名上传物。
- **服务面收敛**：`uploads/` 与代码目录分离，保持 `octet-stream + attachment + nosniff`（现状已做，勿退化）；不提供目录列表。
- **审计**：记录上传者身份（登录后）、大小、时间与哈希。

### 学习要点

- **考什么思路**：把"**这个端点需不需要登录**"当成每次测试的固定自问项。文件名、后缀、MIME 都做得不错的实现，常常整条路径漏掉认证——因为评审者注意力都放在"内容校验"上。
- **与 VER-08 的关系**：同入口的两条独立缺陷线——VER-08 是**输入校验不全**（异常面），VER-16 是**访问控制缺失**（匿名写入）。修复动作不同（一个加字符集/长度校验，一个加认证与配额），所以判定必须分开；只是归档合并到同一篇，避免同一入口出现两份互相矛盾的"修复方案"。
- **同类变体**：
  - 匿名评论、匿名反馈、匿名日志上报接口（内容层面与写入层面双重风险）。
  - 头像/附件上传匿名可用，被当作免费图床/CDN。
  - 临时文件接口无配额，配合大文件上限把磁盘写满（DoS）。
  - "仅前端校验登录态"的 SPA 接口，直接构造请求即可绕过。
