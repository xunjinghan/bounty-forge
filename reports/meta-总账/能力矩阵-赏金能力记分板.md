## 一、掌握度 Rubric（0–5，打分必须能指出对应产物）

| 等级 | 客观标准（满足全部才算到这一级） |
|---|---|
| **0** | 未接触，连原理都说不清 |
| **1** | 能看懂他人报告/能识别代码里有没有对应防护；在加固靶场上证明过"阴性"，但**没在有漏洞目标成功打出来过** |
| **2** | 能照教程/Poc 在已知漏洞靶场复现，讲得清原理；复现依赖现成步骤 |
| **3** | 能在**没给漏洞位置的陌生本地靶场**独立定位并稳定复现，产出完整证据 + 可提交报告 + 自写检测脚本 |
| **4** | 能白盒审源码主动发现 + 黑盒验证 + 写 nuclei 规则/通用 PoC + 给修复 + 在加固/WAF 后完成至少一次绕过 |
| **5** | 能在仿真赏金目标（开源电商/CMS）上独立挖出该类漏洞并组成漏洞链，报告达到漏洞盒子可提交水准，可迁移到真实授权项目 |

> 关键区分：**"证明阴性 / 识别防护"只能到 1 级**。赏金要的是"在有漏洞的地方打出来"，N-01..N-08 这类阴性经验记 1 分，不算实战掌握。

### 五维能力分（P/R/A/B/W，各 0–5，用于看出短板）

| 维度 | 含义 |
|---|---|
| **P** 原理 | 能否讲清根因、底层机制、攻防条件 |
| **R** 复现 | 能否手工稳定复现（含抓包/改包/重放） |
| **A** 自动化 | 能否自写 Python 检测脚本 / nuclei 模板批量验证 |
| **B** 绕过 | 能否在加固、WAF、同源/Token 防护下绕过 |
| **W** 报告 | 能否产出对齐漏洞盒子审核的报告 |

## 二、赏金权重（漏洞盒子 Web 众测 / SRC 实战分布）

- ★★★★★ 业务逻辑（越权 / 支付 / 重置 / 竞态）——赏金最高、扫描器扫不到、最吃人工思路，D1 主攻
- ★★★★ 通用 Web 高危（SQLi / SSRF / 文件上传 / RCE / 认证缺陷）、漏洞链
- ★★★ 组件 CVE（Shiro/Fastjson/Tomcat/WebLogic/Struts2/Spring，靠指纹命中）、信息泄露→接管
- ★★ 反射 XSS / CSRF / 路径遍历 / 低危信息泄露（单独低，常作链条一环）
- ★（拔高/特定项目）内网域渗透、RCE 链——Web 众测少见但单价高，D5 选修
