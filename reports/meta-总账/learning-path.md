## 3. 空白与短板清单（按「赏金回报 / 学习成本」排序）

排序口径：回报取该类漏洞在主流 SRC 与赏金平台的常见定级与受理率；成本取「在本机靶场能否闭环验证」。依据技能文档：`cybermes-bb-methodology`（PART 2 五阶段流、PART 4 误报纪律）、`cybermes-triage-validation`（7 问闸门、NEVER SUBMIT 清单）、`cybermes-report-writing`（定级与标题范式）。

| 优先级 | 空白 | 回报（依据） | 成本 | 现状证据 |
|---|---|---|---|---|
| **P0** | **攻击链闭环与「可复现证据包」**：能把一个低危原语推到实际影响，并留下请求/响应差分 + 定级 | 报告定级与受理率直接决定收益（`cybermes-report-writing` TITLE FORMULA / SEVERITY DECISION GUIDE；`cybermes-triage-validation` Q6「不能只证明技术上可能」） | 低（靶场已具备全部原料） | VULN-03 做对了一次转账闭环，但未记录 HTTP 原始转录、未做 CVSS 校准、未验证 token 跨会话复用性 |
| **P1** | **SSRF 绕过类对抗**（协议降级 / 重定向跟随 / 解析歧义 / DNS rebinding 前置条件） | SSRF 常定为高危（可打元数据/内网），`cybermes-ssrf-server-side-request-forgery` 第 4–9 节整章讲绕过家族 | 中（需自建重定向与 DNS 解析实验环境） | `/fetch` 仅允许 `127.0.0.1` + 端口白名单（`progress.md` §5.3 列为待补面），从未实测重定向跟随与主机解析歧义 |

## 4. 下一步练什么（练习项，每项含判定标准与自证方法）

> 通用纪律（四条，所有练习项都适用）：① 每次练习前先 `GET /__reset` 建立干净基线（**破坏性操作，只在本地靶场执行**），并记录基线 hash；② 结论必须带**请求原文 + 响应原文 + 差分对照**，不接受「我试过，确实可以」；③ 写清「攻击者需要什么前置条件」（账号、另一用户 ID、网络位置）；④ 任何写法都要能在 60 秒内被别人照做复现（`cybermes-triage-validation` 预提交检查表）。

### 练习 A（P0，最高优先）：把 Host 头注入从「中危反射」推到「有影响的链」——或者证明推不动

- 靶场 / 目标类型：`127.0.0.1:8095`；Host 头注入 → 令牌安全 → 账号接管链。
- 已知原料：`/forgot` 反射 `X-Forwarded-Host`；令牌 = `md5(username)`；**当前无 `/reset` 消费端**（本文件 §2 实测）。
- 要做的事（思路，不给 payload）：沿着「令牌从生成到被消费」的完整生命周期把靶场走一遍；对其中的每一跳记录请求/响应；对「无法利用」的每一跳给出**否定证据**（例如端点 404 的统一响应体 hash、同一响应体在不存在资源上也成立）。
- 判定标准（三选一即算完成）：
  1. 找到一条真实可用的消费路径并完成改密，且能给出「重置前口令失效、重置后新口令可登录」的双向证据；
  2. 证明消费端不存在，并把结论写成「Host 注入成立 / ATO 不成立」的定级说明（含 CVSS 3.1 打分与理由）；
  3. 证明令牌虽不可消费，但可与另一原语组合产生新的实际影响（须给出组合后的最小复现步骤）。
- 自证是否学会：合上笔记，向队友口头复述「这条链缺哪一环、缺环的判定证据是什么」，队友能据此独立复现并得出同一结论。
- 参考标准：`cybermes-hunt-forgot-password`（5 类恢复流缺陷）、`cybermes-hunt-host-header`（Phase 1–2）、`cybermes-triage-validation`（Q1/Q6）、`cybermes-report-writing`（定级）。

### 练习 B（P0）：以 `SECRET_KEY` 为核心，做一次**密钥体系专项审计**

- 靶场 / 目标类型：`127.0.0.1:8095`；密钥派生、随机数质量、令牌作用域。
- 已知原料：`/debug` 泄露密钥；CSRF = `HMAC(密钥, 会话 token)`（本文件 §2 已复现逐字节相等）。
- 要做的事（思路）：列出该应用里**所有**依赖长期密钥或用户可控输入生成的凭据；对每一个回答三个问题——「输入是否可预测」「是否绑定到具体会话/用户」「泄露密钥后能否批量推导」；把「能否跨会话复用」「轮换密钥后旧令牌是否失效」作为待实测项。
- 判定标准：产出一张「凭据清单表」（凭据名 / 生成算法 / 输入熵来源 / 绑定对象 / 密钥泄露后的后果），每行都带实测或源码行号依据；对每个「可推导」的凭据给出一次实证。
- 自证是否学会：任取表中一行，仅凭你写的表就能让他人从零复现该结论，且不需要回头读源码。
- 参考标准：`cybermes-hunt-csrf`（令牌绑定与复用检查、SameSite 缺失信号）、`cybermes-hunt-session`、VULN-03 笔记 §1/§5。

### 练习 C（P1）：SSRF 绕过对抗（在自己的实验环境里造可控条件）

- 靶场 / 目标类型：`127.0.0.1:8095` 的 `/fetch`；目标是**判定该白名单的真实边界**，而不是绕过生产系统。
- 已知原料：仅允许 `http`、主机名 `127.0.0.1`、端口白名单（`progress.md` §2 / 侦察证据 `recon-attack-surface-map.json`）。
- 要做的事（思路）：先在本地起一个可控的小服务（302 重定向到其它主机、返回 200/302/非 HTTP 内容各一），把 `/fetch` 指向它，观察**跟随重定向后是否重新校验**；再用等价主机名表示法（同一主机的不同书写形式）考察校验发生在「字符串比较」还是「解析后的主机」层面；对 DNS 重解析类绕过，先写清前置条件再判断本机是否可验证。
- 判定标准：对每一类绕过给出「成立 / 不成立 / 本机不可验证（原因）」三态结论；成立必须有响应体差异证据，不成立必须有对照请求证明校验在何处生效。
- 自证是否学会：能画出该端点的**校验流水线**（取值 → 解析 → 校验 → 发起请求 → 处理响应），并指出校验点位于哪一步、为什么这种位置会产生/不产生绕过。
- 参考标准：`cybermes-ssrf-server-side-request-forgery`（§4 过滤绕过家族、§8 决策树、§9 过滤实现思维）、`cybermes-dns-rebinding-attacks`（前置条件）。

### 练习 D（P3）：竞态/原子性重测（推翻或确认 G4）

- 靶场 / 目标类型：`127.0.0.1:8095`；财务与领取类接口的并发原子性。
- 已知原料：`progress.md` §2 记 G4「10 并发后余额 1999 未变负」——**该判定缺方法论化并发模型**。
- 要做的事（思路）：先读源码确认临界区（读-改-写序列 / 事务边界 / 唯一约束），再设计并发模型（同一账号多请求、多账号同资源、单连接多流），最后用「正确请求 + 并发时序」而不是「畸形请求」去撞击临界区。
- 判定标准：结论必须包含 ① 临界区定位（源码行号）② 并发模型说明 ③ 前后台账实差分（余额/计数/库存）④ 至少 3 次重复的可复现率。**若无法复现，必须写明已排除的可能原因。**
- 自证是否学会：能说出「这是不是竞态」的判据（同一状态被两个请求基于同一旧值写入），并能在不借助工具的情况下手工构造最小并发序列。
- 参考标准：`cybermes-hunt-race-condition`（两种触发原语、单包攻击架构、race-window 估算、反模式）、`cybermes-business-logic-and-idor`（参数篡改与状态机）。

### 练习 E（P2）：端到端「可提交形态」报告演练（选一条已实证漏洞）

- 靶场 / 目标类型：任一条已实证漏洞（建议 VULN-03 或练习 A/B 的结论）。
- 要做的事（思路）：按「标题公式 → 复现步骤（triager 视角）→ 影响 → 修复建议 → 证据附件」组织，**必须**包含一份原始 HTTP 转录（请求与响应全量）与一份差分对照；然后自己做一次 7 问闸门与 CVSS 打分，并写下「为什么不是更低一档」的反驳。
- 判定标准：报告全文无「可能/大概」等模糊定级语；每条影响都能对应到一个实测观测项；修复建议给出优先级与「为什么这个改法能消除根因」。
- 自证是否学会：把报告交给队友，队友能**只按步骤**复现成功；若队友在任一步需要问你，则该步不合格。
- 参考标准：`cybermes-report-writing`（模板与定级）、`cybermes-triage-validation`（7 问、NEVER SUBMIT、CVSS 参考）、`cybermes-evidence-hygiene`、`cybermes-bb-methodology`（PART 4 差分纪律：Body-Diff Rule / 标记法）。

## 5. 方向性提示卡（给 hunter / verifier / scribe）

> 用法：先读「方法论提示」（怎么做），再读「检查清单」（逐项核对），最后才看「具体方向」（往哪里看）。**本卡不提供 payload，不代替挖掘与验证结论。**

### 5.1 hunter（挖掘员）

**提示卡 H1 — VULN-01 已失效，不要沿用旧攻击链前提**
- 方法论提示：把「笔记声称」与「当前运行态」当作两个独立事实源，先做一次最小复现再投入深挖。
- 检查清单：① 复跑 `_evidence/mentor-recheck-20261012.py`；② 对比 `baseline-20261012-154202.json` 的 `password_shape`；③ 确认攻击链每一环今天是否仍然可用。
- 具体方向：当前唯一确认可用的高权入口是种子口令账号；`/debug` 与 CSRF 伪造仍然连通。

**提示卡 H2 — `/forgot` 的令牌目前没有消费端**
- 方法论提示：看到「令牌被生成」不等于「令牌可利用」，必须找到**消费点**（验证端点、状态变更点）才能声称影响。
- 检查清单：① 是否存在消费端点（含不同方法/大小写/路径变体）；② 消费端点的鉴权要求；③ 令牌是否绑定用户/会话/IP；④ 无效令牌的响应是否与有效令牌不同。
- 具体方向：`/reset` 系列返回统一 404；把「Host 注入成立」与「账号接管不成立」分开陈述，后者需要新证据才能改判。

**提示卡 H3 — `/fetch` 的绕过要按「校验发生在哪一步」分类**
- 方法论提示：白名单绕过不是试字符串，而是判定「校验的是原始字符串还是解析后的主机/端口，以及重定向后是否重新校验」。
- 检查清单：① 是否跟随 302；② 跟随之后是否再校验目标；③ 主机等价表示（多种写法）是否都被拒；④ 错误响应能否区分「解析失败」与「校验拒绝」；⑤ 是否总是校验最终目标而非首次目标。
- 具体方向：先自建一个可控重定向服务做对照实验，任何结论都要有「同一请求换一个对照组就失效/生效」的差分证据。

**提示卡 H4 — G4「不可并发击穿」的结论值得重测**
- 方法论提示：并发结论对模型极度敏感；「10 并发」不等于覆盖临界区。先定位临界区，再选并发模型。
- 检查清单：① 源码里读-改-写序列是否有原子条件更新或事务；② 是否所有路径都经过同一原子更新；③ 前后台账实是否一致；④ 复现率是多少。
- 具体方向：`/wallet/withdraw`、`/coupon/claim`、`/order/status` 三个点各出一份并发模型说明。

### 5.2 verifier（验证员）

**提示卡 V1 — 先证伪「400/403 代表防护有效」**
- 方法论提示：状态码不是防护的证据，**响应差异**才是。400 可能来自输入层，403 可能来自 CSRF 层，两者与鉴权层的位置关系决定结论。
- 检查清单：① 该类请求在「畸形体」与「合体空对象」两种输入下分别返回什么（层级陷阱）；② 同一端点在「无凭据 / 有凭据低权 / 有凭据高权」下的三态响应；③ 响应体差异是否可用于枚举。
- 具体方向：`cybermes-triage-validation` 的 LAYER-ORDERING TRAP 章节是标准答案，请对照靶场逐条走。

**提示卡 V2 — 分清「设计加固」与「实现缺陷」**
- 方法论提示：统一 404、泛化错误信息、恒定时间比较，都可能是**有意的加固**；把它们当漏洞会得到错误的定级与报告。
- 检查清单：① 源码里是否有显式注释/常量表达防护意图（如「统一 404，杜绝枚举」）；② 是否有审计日志记录被拒事件（记录行为本身是加固证据）；③ 该行为在所有分支上是否一致（一致 = 设计，不一致 = 缺陷）。
- 具体方向：`target-site/app.py:1210-1222,1246-1259` 是范例，请对照它把 8095 的同名端点比一遍。

**提示卡 V3 — 影响验证要「双向闭合」**
- 方法论提示：能改不代表改成功；改成功不代表影响成立。财务与身份类操作要求**前后双观测**。
- 检查清单：① 操作前的值（不能只看操作后）；② 操作后同一路径再读一次（而非只看响应体声称）；③ 反向确认（旧口令是否失效、新口令是否可登录、接收方是否真的到账）；④ 对照实验（去掉关键要素后是否失败）。
- 具体方向：VULN-03 的双向余额闭环就是模板，后续所有写操作按同一强度复核。

### 5.3 scribe（笔记员）

**提示卡 S1 — 结论必须绑定「时点 + 状态」**
- 方法论提示：同一靶场的结论会随复位、加固、数据库迁移而变；不带时点的笔记会误导下一轮工作。
- 检查清单：① 每条结论是否带采集时间与运行态标识（进程 PID / 库文件 hash / 复位次数）；② 引用的旧结论是否标注「采集时点 + 是否已复核」；③ 被推翻的结论是否显式标注作废原因而非直接删除。
- 具体方向：本文件 §2 表格的写法（旧结论 / 今日实测 / 判定 三列）可直接复用到每份漏洞笔记顶部。

**提示卡 S2 — 证据要分「原始证据」与「结论」两层**
- 方法论提示：报告的可信度来自原始转录，不是叙述。叙述可以被质疑，转录不能。
- 检查清单：① 是否有请求原文（含全部头与体）；② 是否有响应原文（状态行 + 头 + 体）；③ 是否有对照组；④ 是否有工具输出落盘（脚本 + JSON/文本）；⑤ 证据文件是否可被他人重跑。
- 具体方向：`cybermes-evidence-hygiene` 与 `cybermes-report-writing` 的 Supporting Materials 章节。
